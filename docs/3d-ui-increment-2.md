# Studio UI increment 2 — desktop workflow and local persistence

Date: 2026-11-05. Branch: codex/3d-studio-worker. Previous increment: 0c880bd.

## User flow now implemented

1. /studio → prepare avatar: name, height, front/side/back photos.
2. Or prepare t-shirt/shirt: name, front/back, optional detail image.
3. Client decodes images, validates JPG/PNG/WebP, ≤12 MiB/image, dimensions ≥512×512 and ≤40 MP; invalid images show actionable errors.
4. Export a local ZIP containing capture.json, photos/ and PC-README.txt. No network upload, queue enqueue, or inference is simulated. Source photos stay in memory until close/export; downloaded ZIP contains originals and may include original metadata.
5. PC reconstructs outside this web increment and exports existing manifest v1 + self-contained GLB contract.
6. User imports the result, filters/searches shirts, toggles prepared garment meshes, remembers A and compares A/B at a shared camera angle.
7. Name up to 30 look selections in the current bundle. Save the bundle + looks explicitly to IndexedDB to keep across reload. Restore is manual; no automatic display of stored body models.
8. Local storage key uses current authenticated account ID from existing /api/auth/session. This is UI separation, not encryption or protection from people with access to browser storage. Text in UI explains local/shared-device limits.
9. A stored bundle is replaced only by an explicit new Save. Close releases active scene/memory; Delete local copy removes IndexedDB record but does not close an already-open scene. No remote objects are deleted.
10. Export look choices as JSON; this file does not include GLB models, and UI says so.

## Technical contract for PC

ZIP is uncompressed (level 0) to avoid re-compressing photo data. File names are generated by view, never user paths. capture.json:

```json
{
  "schemaVersion": 1,
  "id": "generated-uuid",
  "kind": "avatar | t-shirt | shirt",
  "name": "user label",
  "heightCm": 170,
  "createdAt": "ISO timestamp",
  "status": "input_only",
  "views": [{"view":"front","file":"photos/front.jpg"}]
}
```

heightCm is null for garments. The views list references each included source photo with its decoded format extension. This is input-only, not a queue job and not the GLB output manifest. User must transfer it to PC. The output manifest v1 remains unchanged, so PC's existing export instructions remain compatible.

## Outstanding

No automatic GPU connection, model inference, hosted capture storage, durable queue, cross-device sync or deployed change. Local IndexedDB may be evicted by browser storage policies and is not a substitute for backup. Capture body model quality and real clothes/logo consistency depend on the PC pipeline and remain unverified.
